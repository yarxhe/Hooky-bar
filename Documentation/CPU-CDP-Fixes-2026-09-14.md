# CPU и память локального канала — 14 сентября 2026

Локально установлена версия **1.4.1 (5)**. Без коммита, push, релиза и изменения пользовательских данных. Анимации сохранены; оформление стопки/стикеров не менялось.

## Изменения

- `NativePaneCache`: до четырёх посещённых страниц; к окну прикреплены максимум две. Неактивные страницы отсоединяются, через 8 секунд после закрытия панели освобождаются. Memory pressure освобождает отсоединённые страницы сразу.
- Убран принудительный рекурсивный layout из `updateNSView`. Большое содержимое сохраняет размер 440 × 314, пока внешняя оболочка анимируется.
- Движение цветного фона выполняет Core Animation над подготовленными слоями, без покадрового CPU-рисования `Canvas`. Палитра продолжает плавно меняться; Reduce Motion и остановка скрытых слоёв покрыты тестом. Затраты WindowServer/GPU отдельно не измерялись.
- Локальный CDP-клиент переведён с URLSession на `NWConnection`/`NWProtocolWebSocket`. Hooky не поднимает собственный сервер. Лимиты ответов, закрытие на всех выходах, отбрасывание поздних ответов, 3-секундная пауза между неудачными фоновыми проверками; явные команды обходят отрицательный кэш. Проверка владельца порта остаётся.

## Найденное удержание CFNetwork

Синтетический loopback-сервер отвечает на `/json/list` и `Runtime.evaluate`; до ответа отправляет постороннее CDP-событие. Никакой JavaScript в Яндексе не выполняется. В тесте подменяется только проверка владельца порта и добавляется наблюдатель со слабыми ссылками; транспорт настоящий.

Промежуточный диагностический вариант на URLSession сохранял **3 500 сессий** после 3 500 запросов. Между 1 000 и 3 500 запросами footprint вырос примерно на **77 МиБ**, хотя сервер показывал ноль открытых сокетов. Это не замер старого установленного приложения целиком. Отдельные варианты с callback API, autorelease pool и отключением proxy dictionary не устранили рост.

`leaks -traceTree` связал конкретную сессию с цепочкой `URLProtocol → ProxyConnectionEstablishment → NWIOConnection → CFNetwork WeakTracker<TransportConnection>`. Обычный `leaks` показывал ноль потерянных блоков: достижимое удержание не обязано считаться утечкой этим инструментом. Причина внутри этой версии сетевого стека воспроизведена; универсальный дефект всех версий macOS не утверждается.

После перехода на Network.framework:

| Этап отдельного стресс-процесса | Footprint, МиБ | Живые соединения |
| --- | ---: | ---: |
| 500 успешных запросов | 7,03 | 0 |
| 1 000, прогретая точка | 7,09 | 0 |
| 3 500 | 7,28 | 0 |
| Ещё 500 операций с обрывом (1 000 попыток) | 7,34 | 0 |
| Ещё 500 неудачных discovery | 7,47 | 0 |

Итоговый прирост к прогретой точке около **0,38 МиБ** (в предыдущем смешанном прогоне 0,20 МиБ), без прежнего линейного накопления. Это footprint тестового процесса, не всей Hooky bar. Отдельно проходят тайм-ауты, ответы свыше 512 КиБ, закрытие соединений, посторонние события, отрицательный кэш и немедленный повтор явной команды. Сервер также отклоняет Origin-заголовок, как Chromium при отсутствии разрешённых origins: ослаблять настройки DevTools для нового клиента не требуется.

HTTP-парсер поддерживает Content-Length и close-delimited HTTP/1.x. Не является общим HTTP-клиентом: не следует редиректам, не принимает сжатие/chunked. Это соответствует формированию discovery через `SendJson → SetBody` в [Chromium](https://chromium.googlesource.com/chromium/src/+/master/content/browser/devtools/devtools_http_handler.cc); `SetBody` добавляет [Content-Length](https://chromium.googlesource.com/chromium/src/net/+/4d9e8e1ce35acbb837f7de42523b2a806c85d84a/server/http_server_response_info.h).

**Ограничение:** настоящий Яндекс был закрыт, на сохранённом порту 56574 listener отсутствовал. End-to-end работа с живым плеером и память процесса Electron за часы этим прогоном не подтверждены. Яндекс не перезапускался, debug endpoint не включался, музыка/лайки/очередь не менялись.

## Проверка установленного интерфейса

macOS 27.0 (26A428), 8 логических CPU, дисплей 1512 × 982 @2x, Reduce Motion и Low Power выключены, музыкальных приложений нет. CPU: 100% означает одно полностью занятое ядро; измерение по времени процесса с шагом 0,25 с. Пиковые интервалы не равны длительной нагрузке.

`panel-v1`: два прогревочных и три измеряемых цикла; все открытия, закрытия, вкладки, четыре фильтра буфера и пары прокрутки Dev подтверждены, пропусков нет.

| Сценарий | Средний CPU | p95 CPU |
| --- | ---: | ---: |
| Раскрытие | 27,3% | 43,3% |
| Переключения вкладок | 13,9% | 49,0% |
| Фильтры буфера | 3,5% | 12,7% |
| Dev: прокрутка с паузами сценария | 5,5% | 29,0% |
| Закрытие | 16,1% | 28,5% |
| Восстановление после закрытия | 0,2% | 0,1% |

Медианная память до циклов 51,2 МиБ, после 49,0 МиБ (−2,2 МиБ); максимум по фазам 59,1 МиБ. Тренд после успокоения +0,05 МиБ/цикл, только три измеряемых цикла — не многочасовая гарантия. Первоначальный свежий замер старой сборки остановлен движением мыши до действий; полноценного нового `panel-v1` before/after нет. Значения выше не объявляются автоматическим performance PASS.

Отдельный сценарий `diagnose-dev-entry-ax-v1` совпадает с утренним по конфигурации, окружению и 8/8 проверенным нажатиям Буфер/Dev. Вход в Dev: **15,8 → 12,7%** среднего CPU; p95 **40,7 → 38,9%**. Буфер: **15,2 → 12,1%**. Измеряемые входы не профилировались; отдельный 8-секундный профиль не включён в эти числа. Встроенный общий comparator требует стандартных фаз `panel-v1` и возвращает `Missing comparable measurements`; сравнение здесь ручное, не PASS тест-раннера.

Восьмисекундный пассивный замер открытой Музыки: **0,020% CPU**, 52,03 МиБ. Финальный покой Dev — около 0,02%. Внешний вид фона проверен в установленном приложении. Прежней постоянной CPU-перерисовки фона в этом замере нет. При этом **раскрытие и короткие пики ещё высокие**: проблема CPU не объявляется полностью решённой. Новый профиль Dev всё ещё показывает обычный AppKit layout/SwiftUI display-list, но уже не наш рекурсивный layout внутри `updateNSView`.
