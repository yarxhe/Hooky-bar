# Разработка Hooky bar

[Русский](CONTRIBUTING.md) · [English](CONTRIBUTING.en.md)

Этот документ предназначен для тех, кто собирает Hooky bar из исходников или добавляет новую интеграцию. Пользовательская установка будет распространяться готовым релизным образом и описывается в [README](README.md).

## Требования

- macOS 14 или новее;
- Xcode 26 или новее с macOS 26 SDK: он нужен компилятору для Liquid Glass API, хотя само приложение поддерживает macOS 14 и использует fallback;
- Swift Package Manager (manifest использует tools version 5.9);
- `gh` с выполненным `gh auth login` — только для проверки GitHub Actions в Dev-разделе.

Mac с вырезом рекомендуется для визуальной проверки compact-состояний, но обычная сборка возможна и без него.

## Сборка

```bash
swift build
```

Запуск debug-версии из Swift Package Manager:

```bash
swift run HookyBar
```

Не запускайте одновременно debug-процесс и установленную копию: два экземпляра будут независимо слушать media session и системные события.

## Локальная установка

Скрипт собирает release, создаёт `Hooky bar.app`, устанавливает его в `~/Applications`, перезапускает один свежий экземпляр и добавляет приложение в Login Items:

```bash
./Packaging/install.sh
```

Путь установки можно временно переопределить:

```bash
HOOKYBAR_INSTALL_ROOT=/path/to/folder ./Packaging/install.sh
```

Локальная сборка подписывается ad-hoc с постоянным bundle identifier `com.yarxhe.HookyBar`. Публичный релиз должен использовать Developer ID, notarization и отдельный сценарий упаковки `.dmg`.

## Правило зависимостей

Внешние приложения и macOS API вызываются только через адаптеры:

```text
SwiftUI View → Store → Adapter → macOS / внешнее приложение
```

View не должна запускать AppleScript, читать pasteboard, выполнять CLI или выбирать fallback. Store владеет состоянием и оркестрацией. Adapter выполняет конкретную внешнюю операцию.

Новая интеграция должна следовать [checklist адаптера](Documentation/Adapters.md#checklist-нового-внутреннего-адаптера).

## Стиль изменений

- Сохраняйте существующую модульную структуру; новый внешний сервис получает отдельный adapter-файл.
- Не добавляйте детали конкретного приложения в общий store.
- Обновляйте `@Published` только на main queue.
- Освобождайте timers, watchers и callbacks в `stop`.
- Не храните токены, если можно использовать системную авторизацию или Keychain.
- Новая capability должна быть отражена в настройках и [матрице разрешений](Documentation/Permissions.md).
- Не создавайте новую геометрию и motion для интеграции, если подходит существующая поверхность Hooky bar.

## Pull requests

- Создавайте отдельную ветку от актуальной `master` для каждого самостоятельного изменения.
- Не смешивайте исправление, рефакторинг и новую функцию в одном PR без необходимости.
- Заполните шаблон PR: опишите причину изменения, шаги проверки и связанные Issue или Discussion.
- Для интерфейсных изменений приложите скриншот или видео и проверьте idle, compact и expanded состояния.
- Перед отправкой убедитесь, что в diff нет локальных сборок, секретов и несвязанных файлов.

## Проверка перед коммитом

Минимальный набор:

```bash
swift build
git diff --check
```

Для изменений интерфейса дополнительно проверьте:

- idle, compact и expanded состояния;
- открытие и закрытие при запущенной и остановленной музыке;
- отсутствие второго экземпляра приложения;
- hit areas кнопок, hover и scroll;
- светлые обои под полностью чёрной OLED-поверхностью;
- поведение без необязательных системных разрешений.

Для нового адаптера проверьте отсутствие приложения, закрытый процесс, отказ в разрешении, поздний callback и повторные `start`/`stop`.

## Релизная упаковка

Текущий `Packaging/install.sh` — инструмент локальной разработки, а не публичный installer. Перед первым релизом нужен отдельный pipeline:

1. release-сборка;
2. подпись Developer ID;
3. notarization;
4. создание `.dmg`;
5. проверка установки на чистом пользовательском профиле;
6. публикация готового образа и checksum в Releases.

Пользователь релизной версии не должен устанавливать Swift, клонировать репозиторий или запускать shell-скрипты.
